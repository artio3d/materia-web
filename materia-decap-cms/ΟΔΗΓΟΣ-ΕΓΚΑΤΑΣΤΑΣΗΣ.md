# MATERIA — Οδηγός Εγκατάστασης & Ανάπτυξης (Decap CMS)

## 1. Δομή του Repository

Το repository στο Git πρέπει να έχει ακριβώς αυτή τη δομή (όλα στη ρίζα, χωρίς build step):

```
materia/
├── index.html              ← Η σελίδα (χωρίς πλέον hardcoded περιεχόμενο)
├── style.css               ← Αμετάβλητο
├── main.js                 ← Νέα έκδοση: φορτώνει τα JSON με fetch()
├── admin/
│   ├── index.html          ← Η σελίδα διαχείρισης (Decap CMS)
│   └── config.yml          ← Τα σχήματα των συλλογών (όλα στα Ελληνικά)
├── content/
│   ├── products.json       ← 11 κατηγορίες, 22 υποκατηγορίες, 122 προϊόντα
│   ├── brands.json         ← 42 μάρκες για το ticker
│   ├── blog.json           ← 3 άρθρα
│   ├── careers.json        ← 5 θέσεις εργασίας
│   └── locations.json      ← 3 σημεία εξυπηρέτησης + email
└── images/
    └── uploads/            ← Εδώ αποθηκεύονται οι εικόνες που ανεβάζει η διαχειρίστρια
```

> ⚠️ Το παλιό `data.js` **διαγράφεται** — δεν χρειάζεται πλέον.

> ⚠️ Ο φάκελος `images/uploads/` πρέπει να υπάρχει στο repo. Επειδή το Git δεν
> κρατάει άδειους φακέλους, βάλτε μέσα ένα κενό αρχείο `.gitkeep`.

```bash
git init
git add .
git commit -m "MATERIA: JSON-driven αρχιτεκτονική με Decap CMS"
git branch -M main
git remote add origin https://github.com/USERNAME/materia.git
git push -u origin main
```

## 2. Ανάπτυξη στο Netlify (προτεινόμενο)

Το Decap CMS με **Git Gateway** δουλεύει «με ένα κλικ» μόνο στο Netlify, γι' αυτό το προτείνουμε έναντι του Vercel για αυτό το setup.

### Βήμα 2.1 — Σύνδεση του site
1. Πηγαίνετε στο [app.netlify.com](https://app.netlify.com) → **Add new site → Import an existing project**.
2. Επιλέξτε GitHub και το repository `materia`.
3. Ρυθμίσεις build: αφήστε **κενό** το Build command και βάλτε `/` (ή κενό) στο Publish directory — είναι στατικό site, δεν χρειάζεται build.
4. Πατήστε **Deploy**. Σε ~1 λεπτό το site είναι live.

### Βήμα 2.2 — Ενεργοποίηση Identity (σύνδεση διαχειρίστριας)
1. Στο dashboard του site: **Site configuration → Identity → Enable Identity**.
2. Στο **Identity → Registration**, επιλέξτε **Invite only** (ώστε να μην μπορεί να γραφτεί οποιοσδήποτε).
3. Στο **Identity → Services → Git Gateway**, πατήστε **Enable Git Gateway**. Αυτό επιτρέπει στο CMS να κάνει commits στο repo *εκ μέρους* της διαχειρίστριας, χωρίς εκείνη να χρειάζεται λογαριασμό GitHub.

### Βήμα 2.3 — Πρόσκληση της διαχειρίστριας
1. **Identity → Invite users** → βάλτε το email της.
2. Θα λάβει email με link «Accept the invite». Το link την οδηγεί στο site, όπου ορίζει κωδικό (το script στο `index.html` την ανακατευθύνει αυτόματα στο `/admin/`).
3. Από εκεί και πέρα, μπαίνει πάντα από το **`https://yoursite.netlify.app/admin/`** με email + κωδικό.

### Βήμα 2.4 — Πώς δουλεύει καθημερινά
- Ανοίγει το `/admin/`, βλέπει 5 ενότητες στα Ελληνικά: Προϊόντα, Συνεργάτες/Μάρκες, Άρθρα, Θέσεις Εργασίας, Καταστήματα.
- Κάνει αλλαγές → πατάει **Save**. Με το editorial workflow, η αλλαγή πάει σε στήλη «Drafts» → «Ready» → **Publish**.
- Το Publish κάνει αυτόματα commit στο GitHub → το Netlify κάνει redeploy → σε ~1 λεπτό η αλλαγή είναι live.

> Αν προτιμάτε **άμεση** δημοσίευση χωρίς στάδια, διαγράψτε τη γραμμή
> `publish_mode: editorial_workflow` από το `admin/config.yml`.

## 3. Εναλλακτικά: Vercel

Το Vercel φιλοξενεί το στατικό site εξίσου καλά, αλλά **δεν έχει** Identity/Git Gateway. Θα χρειαστείτε είτε:
- το **GitHub backend** του Decap (η διαχειρίστρια θα χρειαστεί δικό της λογαριασμό GitHub με πρόσβαση στο repo και ένα OAuth app), είτε
- εξωτερικό OAuth provider.

Για μη τεχνική διαχειρίστρια, το Netlify + Identity είναι σαφώς η απλούστερη διαδρομή.

## 4. Τοπική δοκιμή (για τον developer)

Τα `fetch()` δεν δουλεύουν με διπλό κλικ στο `index.html` (πρωτόκολλο `file://`). Σηκώστε τοπικό server:

```bash
cd materia
python3 -m http.server 8000
# → http://localhost:8000
```

Για τοπική δοκιμή του CMS χωρίς login, προσθέστε προσωρινά στο `admin/config.yml`:
```yaml
local_backend: true
```
και τρέξτε σε δεύτερο terminal: `npx decap-server`. **Αφαιρέστε το πριν το deploy.**

## 5. Τι αλλάζει τεχνικά (σύνοψη για τον developer)

| Πριν | Μετά |
|---|---|
| `data.js` με global `productsData` (object με keys) | `/content/products.json` με `categories` **array** (CMS-friendly) |
| Blog/Careers/Locations hardcoded στο `index.html` | Άδεια containers (`#blog-grid`, `#job-list`, `#locations-list`) που γεμίζουν από JSON |
| `main.js` διάβαζε globals συγχρονικά | `Promise.all` + `fetchJSON()` με fallbacks στο `DOMContentLoaded` |
| AOS init αμέσως | AOS init **μετά** το render των δυναμικών στοιχείων |
| Bug: λάθος προϊόν στο detail όταν υπήρχε ενεργή αναζήτηση (filtered index) | Διορθώθηκε — αποθηκεύεται το αρχικό index (`origIdx`) |
| Raw HTML injection από τα δεδομένα | Όλα τα CMS δεδομένα περνούν από `esc()` (XSS protection) |
